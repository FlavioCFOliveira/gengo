# WordsPT

## Overview

`WordsPT` is a gengo feature that generates plausible pseudo-words that follow
the morphological and phonotactic patterns of European Portuguese (pt-PT). A
pseudo-word is an invented, rule-generated sequence that looks and reads like a
real Portuguese word but is not required to be an actual dictionary entry. The
feature produces words for every Portuguese word class, inflects open-class
words according to the regular pt-PT paradigms, and applies pt-PT graphic
accentuation deterministically.

`WordsPT` follows the gengo design philosophy: a simple one-call API, sensible
defaults, zero external dependencies, minimal allocations, a small memory
footprint, and fast execution.

This document is the single source of truth for the WordsPT feature. It defines
the public surface, the cross-cutting semantics, the technical constraints, and
the acceptance criteria. The linguistic detail is split across three companion
documents:

- [wordspt-generation-model.md](wordspt-generation-model.md) defines the
  three-layer generation model (phonotactics, morphology, accentuation).
- [wordspt-open-classes.md](wordspt-open-classes.md) defines the generated
  open classes (noun, adjective, verb, adverb) and their inflection rules.
- [wordspt-closed-classes.md](wordspt-closed-classes.md) defines the curated
  closed-class lists (article, pronoun, numeral, preposition, conjunction,
  interjection).

## Definitions

The following terms are used consistently across all WordsPT documents.

- **Pseudo-word**: an invented, rule-generated sequence that conforms to pt-PT
  morphology and phonotactics. It is not guaranteed to be a real word.
- **Open class**: a word class whose members WordsPT generates by morphology
  (noun, adjective, verb, adverb). Open classes are productive.
- **Closed class**: a word class whose members WordsPT selects from a curated,
  exhaustive list of real pt-PT single words (article, pronoun, numeral,
  preposition, conjunction, interjection). Closed classes are not generated by
  morphology.
- **Stem**: the syllable sequence produced by the phonotactic layer, before any
  class ending or inflection is applied.
- **Ending**: the class-specific final segment that marks the word class (for
  example the noun ending `-cao` or the adjective ending `-oso`).
- **Inflection**: the change applied to a word to express gender, number,
  degree, or a verb paradigm slot.
- **Graphic accent**: a written diacritic required by pt-PT orthography (acute,
  circumflex, grave, tilde, cedilla).
- **Tonic syllable**: the stressed syllable of a word.
- **Character**: one Unicode code point (one Go rune). A single accented letter
  such as `a` with an acute accent counts as one character even though it
  occupies more than one UTF-8 byte.

## Scope

### In scope

- Generation of open-class pseudo-words (noun, adjective, verb, adverb) with
  the inflections defined in [wordspt-open-classes.md](wordspt-open-classes.md).
- Selection of closed-class real single words from curated lists defined in
  [wordspt-closed-classes.md](wordspt-closed-classes.md).
- Deterministic application of pt-PT graphic accentuation, in full compliance
  with the Acordo Ortográfico da Língua Portuguesa.
- A public Go API in the main `gengo` package, as defined in this document.

### Out of scope

- Real-word validation. Generated open-class words are not checked against any
  dictionary and may coincide with real words only by chance.
- Multi-word forms of any kind. WordsPT is a single-word generator. Compound
  numbers, verbal locutions, adverbial locutions, prepositional locutions,
  analytic verb tenses, comparative degrees, the relative superlative, and the
  analytic absolute superlative are all excluded.
- The archaic second person plural verb paradigm (the "vos" verb forms such as
  `falais` and `falardes`). See the note under Persons in
  [wordspt-open-classes.md](wordspt-open-classes.md). Archaic-but-real "vos"
  forms that are closed-class words (for example the pronoun `vos` and the
  possessive `vosso`) remain in scope for the pronoun list.
- The simple pluperfect indicative (for example `falara`).
- Brazilian Portuguese spelling and morphology. WordsPT targets pt-PT only.
- Any cryptographic or security use. WordsPT draws from `math/rand/v2` and is
  not suitable for secrets.

## Word class taxonomy

WordsPT recognises every Portuguese word class and divides them into two groups.

| Group | Word class | Portuguese name | How WordsPT produces it |
|-------|------------|-----------------|-------------------------|
| Open | Noun | Substantivo | Generated by morphology; inflects for gender and number |
| Open | Adjective | Adjetivo | Generated by morphology; inflects for gender, number, and degree |
| Open | Verb | Verbo | Generated by morphology; conjugated across the regular paradigm |
| Open | Adverb | Advérbio | Generated by morphology; productive `-mente` adverbs; invariable |
| Closed | Article | Artigo | Selected from a curated real list |
| Closed | Pronoun | Pronome | Selected from a curated real list |
| Closed | Numeral | Numeral | Selected from a curated real list |
| Closed | Preposition | Preposição | Selected from a curated real list |
| Closed | Conjunction | Conjunção | Selected from a curated real list |
| Closed | Interjection | Interjeição | Selected from a curated real list |

The detailed characteristics of each class are defined in
[wordspt-open-classes.md](wordspt-open-classes.md) and
[wordspt-closed-classes.md](wordspt-closed-classes.md).

## Generation model

WordsPT builds every open-class word through three ordered layers. The layers
are specified in full in
[wordspt-generation-model.md](wordspt-generation-model.md); they are summarised
here.

1. **Syllabic phonotactics**: build a stem as a sequence of syllables of the
   form `(onset)(nucleus)(coda)`, using real pt-PT sound inventories with
   frequency weights, positional constraints, and valid inter-syllable
   transitions.
2. **Morphology**: apply the class ending and the requested inflection over the
   stem.
3. **Graphic accentuation**: place graphic accents deterministically, because
   the tonic syllable is controlled by the generator.

Closed-class words skip all three layers; the generator selects them directly
from curated lists.

## Public API

All identifiers are English. All functions live in the main `gengo` package.
All functions return a `string`, except `WordsPT`, which returns `[]string`.
No function returns an error and no function panics.

WordsPT is exposed through two parallel surfaces, exactly as the rest of the
gengo package is:

- **Package-level functions** (for example `WordPT`, `NounPTOf`, and `WordsPT`)
  draw from the global, automatically seeded `math/rand/v2` source. They are safe
  for concurrent use by multiple goroutines and are the right choice when
  reproducibility is not required.
- **`*Generator` methods** mirror every package-level function one to one (for
  example `(g *Generator) WordPT()`, `(g *Generator) NounPTOf(...)`, and
  `(g *Generator) WordsPT(...)`). A `*Generator` draws from its own explicit,
  seeded source, created with `gengo.New(seed)` or `gengo.NewSource(src)`, so the
  same seed always produces the same sequence of words. A `*Generator` is not
  safe for concurrent use; the caller uses one `Generator` per goroutine.

Every one of the seventeen WordsPT functions listed below, including the
open-class generators, the closed-class selectors, and `WordsPT`, is also exposed
as a `*Generator` method with the same name, parameters, and result. The table
below lists the package-level form; the method form is identical, with a
`(g *Generator)` receiver.

### Enumerations

Every enumeration uses its zero value as `Any`, meaning "choose at random among
the valid options". WordsPT reuses the existing `LengthTypeWords` type on the
same principle.

| Type | Values | Zero value |
|------|--------|------------|
| `Gender` | `Any`, `Masculine`, `Feminine` | `Any` |
| `Number` | `Any`, `Singular`, `Plural` | `Any` |
| `Mood` | `Any`, `Indicative`, `Subjunctive`, `ImperativeAffirmative`, `ImperativeNegative`, `Infinitive`, `Gerund`, `Participle` | `Any` |
| `Tense` | `Any`, `Present`, `Imperfect`, `Preterite`, `Future`, `Conditional` | `Any` |
| `Person` | `Any`, `First`, `Second`, `Third` | `Any` |
| `Degree` | `Any`, `Positive`, `Superlative` | `Any` |
| `LengthTypeWords` (existing) | `SmallLengthWord` (1 to 4 characters), `MediumLengthWords` (5 to 8 characters), `BigLengthWords` (9 to 30 characters) | Any value outside `{1, 2, 3}`, including the zero value, means the full range (`Any`) |

`Tense` value `Conditional` corresponds to the Portuguese "condicional"
(also called "futuro do pretérito"). `Tense` value `Preterite` corresponds to
the Portuguese "pretérito perfeito".

## Cross-cutting semantics

These rules apply to every WordsPT function.

### The `Any` value

For each enumeration parameter, the `Any` value (the zero value) means "choose
at random, with the generator's natural weighting, among the options that are
valid for the word being produced". A function whose short form takes no
options (for example `NounPT`) is exact sugar for the long form with every
option set to `Any`.

### Normalization of impossible combinations

Some option combinations are grammatically impossible (for example a second
person plural verb form, which does not exist in the pt-PT paradigm supported
here). WordsPT never returns an error and never panics for such a request.
Instead it normalizes the request to the nearest valid form and produces that
form. The complete normalization rules are defined in
[wordspt-open-classes.md](wordspt-open-classes.md#normalization-of-impossible-combinations).
Every normalization is deterministic and documented.

### Length

Length is always measured in characters, where one character is one Unicode
code point (one Go rune), as defined under Definitions. Length is controlled
through `LengthTypeWords`:

- `SmallLengthWord`: 1 to 4 characters.
- `MediumLengthWords`: 5 to 8 characters.
- `BigLengthWords`: 9 to 30 characters.
- Any other value, including the zero value, means the full range and is
  treated as `Any`.

Length applies only to open classes. Closed-class functions ignore the length
concept entirely, because their output is a fixed real word.

If a requested length category cannot contain any valid word of the requested
class (for example a `-mente` adverb requested in the `SmallLengthWord`
category, whose 4-character ceiling is below the shortest possible `-mente`
adverb), WordsPT normalizes the length upward to the smallest category that can
contain a valid word of that class. Length is never normalized downward. The
per-class minimum viable length is derived from the phonotactic and
morphological rules and is defined in
[wordspt-open-classes.md](wordspt-open-classes.md#minimum-viable-length-per-class).

### Natural distribution

`WordPT`, `WordPTByLengthType`, and `WordsPT` produce words across all ten word
classes with a natural distribution that approximates the relative frequency of
each word class in European Portuguese running text. Within an open class, the
length categories follow the natural length distribution already used by the
existing `Words` function (`WordLengthRatio`). The class-frequency weighting is
defined as a static weight table whose concrete weights are sourced from an
authoritative pt-PT frequency corpus, mirroring how `WordLengthRatio` encodes the
length distribution. Sourcing and encoding these weights is a data requirement
scheduled for the orchestration phase, the sprint that implements `WordPT`,
`WordPTByLengthType`, and `WordsPT`; it is not required for the foundational
generation engine. See Open Items for the recorded decision.

### Capitalization

Every WordsPT output is lowercase, with correct graphic accents. WordsPT never
capitalises an output, even for classes whose members are often capitalised in
running text.

### Encoding

Every WordsPT output is valid UTF-8. Accented letters are encoded as their
standard pt-PT code points.

## Constraints

- WordsPT lives in the main `gengo` package and follows the flat,
  one-file-per-category layout. It is implemented in its own source file (for
  example `wordspt.go`) plus a data file for the static tables and lists (for
  example `wordspt_data.go`).
- WordsPT exposes two randomness surfaces, consistent with the rest of the gengo
  package. The package-level functions draw from the global `math/rand/v2`
  source, which is automatically seeded and safe for concurrent use. The mirrored
  `*Generator` methods draw from the explicit, seeded source of a `Generator`
  created with `gengo.New` or `gengo.NewSource`, which makes their output
  reproducible.
- The internal WordsPT generation engine takes an injectable `*rand.Rand` source
  and is shared by both surfaces. The package-level functions pass the global
  source and the `*Generator` methods pass the generator's own source, so there
  is no duplication of generation logic between the two surfaces.
- WordsPT has zero external dependencies. It uses only the Go standard library.
- WordsPT is rune and UTF-8 oriented. This differs from the rest of the gengo
  package, which is ASCII and byte oriented; pt-PT accents require rune
  handling.
- All static data (syllable inventories, inflection and conjugation tables, and
  closed-class lists) is embedded in the package as static tables. No data is
  read from external files or network sources at run time.
- Each word is assembled in a single reusable buffer, with exactly one final
  `string` allocation per generated word.
- All linguistic data is sourced from authoritative pt-PT references, including
  the Acordo Ortográfico da Língua Portuguesa and reference grammars such as
  Cunha and Cintra, "Nova Gramática do Português Contemporâneo". No linguistic
  data is guessed.

## Acceptance criteria

The following criteria are measurable and are validated over a large sampled
run (at least 100000 generated words per applicable function, unless stated
otherwise).

1. **Class conformance (open classes)**: every word produced by `NounPT`,
   `NounPTOf`, `AdjectivePT`, `AdjectivePTOf`, `VerbPT`, `VerbPTOf`, `AdverbPT`,
   and `AdverbPTByLengthType` matches the class-specific morphological pattern
   defined in [wordspt-open-classes.md](wordspt-open-classes.md).
2. **Verb paradigm correctness**: every verb produced by `VerbPTOf` matches the
   regular conjugation slot addressed by the resolved mood, tense, person, and
   number, for the conjugation class implied by its infinitive ending
   (`-ar`, `-er`, or `-ir`).
3. **Preterite versus present distinction**: for first-conjugation (`-ar`)
   verbs, the first person plural preterite indicative carries an acute accent
   on the theme vowel and is orthographically distinct from the first person
   plural present indicative. Modelled on the verb `falar`, the present is
   `falamos` and the preterite is `falámos`, in line with pt-PT usage.
4. **Closed-class membership**: every word produced by `ArticlePT`, `PronounPT`,
   `NumeralPT`, `PrepositionPT`, `ConjunctionPT`, and `InterjectionPT` is a
   member of the corresponding curated list defined in
   [wordspt-closed-classes.md](wordspt-closed-classes.md), and every member of
   each curated list is reachable.
5. **`Any` semantics**: for each function, calling it with every option set to
   `Any` produces, over the sampled run, at least one word for every valid
   value of every applicable option.
6. **Normalization semantics**: for every impossible option combination listed
   in
   [wordspt-open-classes.md](wordspt-open-classes.md#normalization-of-impossible-combinations),
   the function returns the documented nearest valid form, never an error and
   never a panic.
7. **Encoding and case**: every output is valid UTF-8 and contains no uppercase
   letter.
8. **Length conformance**: for every open-class function call with a length
   category `l` in `{SmallLengthWord, MediumLengthWords, BigLengthWords}` that
   is viable for the class, every output has a character count within the range
   of `l`. When `l` is unviable for the class, every output has a character
   count within the range of the normalized-up category.
9. **Length independence of closed classes**: closed-class functions produce
   the same set of outputs regardless of any length concept.
10. **Accentuation correctness**: over the sampled run, every generated word is
    orthographically correct with respect to the pt-PT accentuation rules
    defined in
    [wordspt-generation-model.md](wordspt-generation-model.md#layer-3-graphic-accentuation),
    including the placement of acute, circumflex, grave, and tilde accents, the
    cedilla rule (a cedilla appears only before `a`, `o`, or `u`, and never in
    initial position), and the nasal diphthongs.
11. **Empty slice contract**: `WordsPT(n)` returns a non-nil empty slice when
    `n` is less than or equal to zero, and a slice of exactly `n` elements
    otherwise.
12. **Allocation budget**: generating a single open-class word performs exactly
    one `string` allocation, as demonstrated by an allocation benchmark.

## Open Items

Every item below was raised as an open decision during specification and has now
been resolved by the user. Each item is retained as a decision record so that its
rationale stays visible and no assumption is silently baked into the
specification. No item below currently blocks implementation.

1. **Seed API and `Generator` mirroring (RESOLVED).** WordsPT is not global-only.
   In addition to the package-level functions, every WordsPT function is exposed
   as a method on the existing seeded `Generator` type (`gengo.New`,
   `gengo.NewSource`), exactly as the rest of the gengo package already mirrors
   its functions. This covers all seventeen WordsPT functions, including the
   open-class generators, the closed-class selectors, and `WordsPT`. The two
   surfaces share a single internal generation engine that takes an injectable
   `*rand.Rand` source, so there is no duplication of generation logic: the
   package-level functions pass the global source and the `*Generator` methods
   pass the generator's own source. The package-level and `*Generator` surfaces
   are specified under Public API, and the shared-engine design is recorded under
   Constraints.

2. **Class-frequency weight table (RESOLVED as a data requirement).** The natural
   distribution across word classes for `WordPT`, `WordPTByLengthType`, and
   `WordsPT` is encoded as a static weight table whose concrete weights are
   sourced from an authoritative pt-PT frequency corpus, mirroring how the
   existing `WordLengthRatio` encodes the length distribution. Sourcing and
   encoding these weights is a documented data requirement scheduled for the
   orchestration phase, the sprint that implements `WordPT`, `WordPTByLengthType`,
   and `WordsPT`. It is not a blocker for the foundational generation engine.

3. **Verb normalization targets (RESOLVED).** The nearest-valid-form targets for
   impossible verb combinations are confirmed as the deterministic normalization
   matrix defined in
   [wordspt-open-classes.md](wordspt-open-classes.md#normalization-of-impossible-combinations):
   a second person plural request normalizes to third person plural (the `vocês`
   agreement); a first person singular imperative request normalizes to first
   person plural; a subjunctive `Preterite` request normalizes to `Imperfect`;
   and a subjunctive `Conditional` request normalizes to `Future`. These targets
   are consistent with the approved principle of normalizing to the nearest valid
   form and never returning an error or panicking.

4. **Negative imperative (RESOLVED).** The negative imperative in pt-PT is
   periphrastic: it is formed with the particle `não` followed by the present
   subjunctive form, and is therefore a multi-word construction. Because WordsPT
   is a single-word generator, the `ImperativeNegative` mood emits only the verb
   form, which coincides with the present subjunctive form for the imperative
   persons. WordsPT does not emit the `não` particle. This behaviour is specified
   in [wordspt-open-classes.md](wordspt-open-classes.md#verb-verbo).
